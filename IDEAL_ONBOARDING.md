# LogicGate Connector — идеальный первый запуск

Источник: `ONBOARDING_FIRST_LAUNCH_STANDARD.md` (портфельный стандарт, см.
Vanta/Drata Connector). Целевой пользователь: Risk/Compliance-менеджер,
использующий LogicGate Risk Cloud для risk register, vendor assessments или
incident management.

## 1. Credential type
Статический API Token (Admin > API Tokens в LogicGate), плюс необязательный
base_url для нестандартных инстансов.

## 2. Идеальный флоу
1. **Первое открытие** — `Empty` с объяснением: "создайте API-токен в LogicGate
   (Admin > API Tokens) и вставьте его сюда — доступ будет ровно таким, какие
   права вы дали этому токену".
2. **Форма подключения** — Label (текст) + API Token + необязательный base_url.
3. **После успеха** — сразу показывается список подключённых Applications
   (Risk Register, Vendor Assessments и т.д. — как настроено у клиента), а не
   общий дашборд, потому что у LogicGate нет фиксированного "правильного"
   первого экрана: структура целиком зависит от конфигурации клиента.
4. **Работа с Records** — пользователь выбирает Application → видит список его
   Records → может открыть один Record и увидеть все его поля как есть (без
   попытки угадать/переименовать пользовательские поля клиента).
5. **Ошибка недостаточных прав (401/403)** — конкретное сообщение: "у этого
   токена в LogicGate нет доступа к этому Application — проверьте права в
   Admin > API Tokens".
6. **Множественные аккаунты** — поддерживаются несколько сохранённых
   подключений с явным label, как в Vanta/Drata.

## 3. Особенность по сравнению с Vanta/Drata
Здесь нет предсказуемых "Risk"/"Control" сущностей на уровне UI — интерфейс
должен быть построен вокруг Applications/Records/Fields, а не жёстко
закодированных бизнес-объектов. См. `UI_COMPONENT_PLAN.md`.
